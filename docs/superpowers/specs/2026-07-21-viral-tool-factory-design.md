# 🅰 病毒工具工厂 · Phase 1 设计(2026-07-21)

## 目标
把 AI 手相(palm)已验证的"图像/输入 → 种子 → 内容 → 分享卡 → 分享即解锁 → 引流私域"模型,**抽成一台可复用的配置化引擎**,并用它做出首批 3 个新病毒工具(网站版),跑通"量产 + 裂变"这条流水线。服务 Zion 的"可裂变造币机器":工具免费引流 → 关注公众号/进星球 → 下游变现。

## 范围
**Phase 1 做**:引擎 + 3 个工具(AI 合婚/配对度、年度/本命关键词、AI 起名)+ 聚合入口页 `/ce`,全部网站版,复用 qizh.space + 现有金黑设计系统。
**不做(后续轮次)**:小程序版;直接付费/收款;塔罗/星相/面相/MBTI 等更多工具(引擎跑通后各写一份配置即可增);后台可视化配置系统。

## 核心原则:内容库为主,LLM 为例外
免费 LLM(智谱)质量弱,**不作为内容生成主力**。
- **内容库 + 种子组合(主力,零 LLM)**:每个工具的文案来自 Zion 一次性写好的**内容库(模板/评语/词库)**,由确定性种子做组合选择。质量可控、秒出、免费、离线可用、同输入同结果。变化靠"组合爆炸",不靠模型。用于:合婚、年度关键词(及后续大多数工具)。
- **LLM 直接生成(仅起名)**:起名天生需要"生成",接受免费模型质量;LLM 挂了/无 key 时退回一版简单模板,永不白屏。**全站只有起名这一个工具依赖 LLM。**

## 架构
配置化引擎 = **一套共享运行时 + 每个工具一份配置**。单代码库。逻辑与渲染分离(为将来整体移植小程序留口)。

数据流:
```
用户输入 → 归一化 → 内容哈希(定种子)
  → 分支:  内容库模式 → 种子驱动从内容库组合出结果
           LLM 模式(仅起名) → 按配置 prompt 调 LLM(失败→模板兜底)
  → 按"结果结构"渲染报告(人设标签 / 分数 / 分段解读)
  → 生成分享卡(canvas,套该工具卡模板,带公众号/星球二维码)
  → 分享即解锁完整解读 + 卡上 QR 引流私域
```

### 共享运行时组件(大多从 palm 提炼/泛化)
- **imgHash / 输入哈希**:图像走 aHash+dHash(palm 现成);纯文字/双人输入走字符串哈希(xmur3)。→ 确定性种子。
- **种子 PRNG**:xmur3 + mulberry32(palm 现成),取代所有 Math.random,保证同输入同结果、跨输入不同。
- **wpick / pickR**:种子驱动的加权抽取 / 数组抽取(palm 现成)。
- **内容库选择器**:按种子从工具配置的内容库里组合出各分段文案(palm 的 assemble/LEX 泛化版)。
- **评分 & 标签**:按配置的评分表/标签规则由种子算出(palm 的 scores/tagOf 泛化)。
- **LLM 调用 + 兜底**:仅 LLM 模式用;复用 palm 的直连智谱 + stripBox + 正则取 JSON + 失败回退。
- **渲染器**:按"结果结构"(标签/四维/分段 + 锁区)统一渲染;复用 palm 的 renderReport + 锁区/blur。
- **分享卡 drawCard**:canvas 竖版海报,套工具卡模板,底部画 `/wechat-qr.png`(公众号)/可选 `/planet-qr.png`;复用 palm drawCard + loadWxQR。
- **分享即解锁 + 引流**:点分享生成卡 = 解锁完整解读(palm 现成);卡带 QR + "微信搜「Zion降噪」";订阅条 + /join 链接。
- **兜底/错误**:内容库工具永不白屏;LLM 工具失败退模板。
- **微信引导**:复用 `/wxtip.js`。

### 一份"工具配置"的形状
```
{
  id, 名字, 图标(emoji), 一句话说明,
  输入定义: [ 字段/选项 | 单图 | 双人 ],      // 决定输入 UI 与哈希来源
  机制: 'lib' | 'llm',                         // 内容库 or LLM 生成
  种子逻辑: (归一化输入)=>种子,
  内容库: { 分段→加权文案池, 标签规则, 评分表, 稀有项加权 }   // lib 模式
  prompt模板 / 结果解析: ...,                  // llm 模式(仅起名)
  结果结构: [ 人设标签, 四维/分数(可选), 分段解读, 锁区分段 ],
  分享卡模板: { 标题, 副标, 展示字段, 钩子句 },
  文案基调
}
```
加新工具 = 新增一份配置(+写它的内容库/prompt),不改引擎。

## 首批 3 个工具

### 1. AI 合婚 / 配对度(双人 · 内容库)
- 输入:两个人的名字(可选生日/属相)。种子 = 两输入归一化后的哈希(A+B 顺序无关)。
- 输出:配对度总分 + 人设标签(如【互补拉扯型】)+ 分段解读(性格契合/沟通/雷区/旺不旺)+ 一句毒舌钩子。
- 内容库:各维度加权文案池,按种子组合;稀有"天生一对/前世冤家"加权抽签。
- 裂变最强(情侣/闺蜜/暧昧对象都想测)。

### 2. 年度 / 本命关键词(纯文字 · 内容库)
- 输入:3–4 道趣味选择题(如"最近更像哪种动物""今年最想要什么")——**不采集真实生日/隐私,降门槛**。种子 = 选项组合的哈希。
- 输出:年度关键词(1–3 个)+ 本命人设 + 运势分段 + 金句。门槛最低、最好做。
- 内容库:关键词词库 + 模板句,种子组合。

### 3. AI 起名(文字 · LLM · 唯一用 LLM 的)
- 输入:姓、性别、期望寓意/风格(可选五行)。
- 输出:3–5 个候选名 + 每个的寓意解释 + 音律/搭配点评。LLM 生成;失败 → 模板兜底(给通用好字组合)。
- 说明:接受免费模型质量;是引擎"llm 模式"的样板。

> 面相(图像模式)不在首批——palm 已证明图像路径;等引擎跑通写份配置即可加。

## 入口 / 落位 / 品牌
- 复用 qizh.space,新增聚合入口页 **`/ce`(AI 测测)**:金黑卡片墙列出所有工具(含 palm),每个工具独立页 + 独立分享卡。
- 每个工具独立可分享(自己的卡),也从 /ce 互相导流。
- 复用现有设计系统(金黑、字体、光标、噪点)。

## 微信封域名对策
qizh.space 在微信内被硬封。故裂变**不靠点链接**:
- 分享卡是**图片**,朋友圈可传;卡上带**公众号/星球二维码**(微信长按识别原生可用);
- 文案引导"微信搜「Zion降噪」"(搜公众号名封不了);
- 网页版另吃站外(X/小红书/浏览器)流量。
- `/wxtip.js` 兜非微信 webview。

## 变现 / 引流
免费玩 + 分享即解锁 + 卡带 QR → 关注公众号 / 进星球 → 私域下游变现。Phase 1 不直接收钱。

## 小程序(未来)
不在 Phase 1。引擎按"逻辑(哈希/种子/内容库选择/评分)与渲染(DOM/canvas)分离"写,以便之后整体移植小程序(小程序原生、不受封域名影响、可接微信支付)。

## 验收标准(高完成度)
每个工具:本地起服务 + 浏览器真机跑通——① 输入→出结果(内容库组合正确/起名 LLM 出货)② 同输入同结果、跨输入不同 ③ 分享即解锁生效 ④ 分享卡出图且带 QR ⑤ 移动端排版正常 ⑥ 控制台零报错。/ce 聚合页与各工具互链正确。全绿再 push。
